# План проекта: трекер личной эффективности (Time Tracker)

> Веб-приложение для отслеживания действий в течение дня, анализа распределения
> времени и статистики по неделям/месяцам. Mobile-first.

---

## 1. Стэк (зафиксировано)

### Frontend
- **React 18 + TypeScript** — SPA (без Next.js, см. обоснование ниже).
- **Vite** — сборка и dev-сервер.
- **SCSS-модули** (`*.module.scss`) — изоляция стилей по компонентам.
- **Zustand** — глобальный UI-стейт (выбранная дата, фильтры, текущий юзер).
- **TanStack Query (React Query)** — серверный стейт: кэш, загрузка, инвалидация
  запросов к API. (Zustand для UI, React Query для данных — это разные задачи,
  они не конкурируют, а дополняют друг друга.)
- **React Router v6** — навигация между страницами.
- **Recharts** — графики (адаптивные, простые, хорошо ложатся на мобилку).
- **axios** — HTTP-клиент с интерсепторами для JWT.
- **date-fns** — работа с датами/интервалами.

### Backend
- **Python 3.12 + Django 5 + Django REST Framework**.
- **djangorestframework-simplejwt** — JWT-аутентификация (access + refresh).
- **django-cors-headers** — CORS для фронта.
- **PostgreSQL** — БД.
- **drf-spectacular** — авто-документация API (Swagger/OpenAPI).

### Качество кода / тулинг
- Frontend: **ESLint** (+ `eslint-plugin-jsx-a11y` для доступности), **Prettier**,
  **stylelint** (`stylelint-config-standard-scss`).
- Backend: **Ruff** (линтер+форматтер), **mypy** (типы, опционально).
- **EditorConfig**, **pre-commit** хуки (прогон линтеров перед коммитом).
- Контейнеризация: **docker-compose** (postgres + backend + frontend) для воспроизводимого запуска.

### Почему React+Vite, а не Next.js
- Всё приложение за авторизацией → SSR/SEO (главная ценность Next) бесполезны.
- Бэкенд уже на Django → серверные возможности Next дублируют его.
- Меньше сложности для незнакомого фреймворка; фокус на логике приложения.

## 2. Модель данных (PostgreSQL)

### User (стандартный `django.contrib.auth.User` или кастомный)
- Мультиюзер: каждая запись привязана к пользователю.

### Category
| поле          | тип                                   | описание                              |
|---------------|---------------------------------------|---------------------------------------|
| id            | PK                                    |                                       |
| user          | FK(User), nullable                    | `null` = глобальная дефолтная категория |
| name          | CharField                             | «Тренировка», «Чтение», «Тикток»      |
| color         | CharField (hex)                       | для графиков и ленты дня              |
| icon          | CharField                             | имя иконки (эмодзи/lucide)           |
| kind          | Enum: `productive` / `neutral` / `waste` | для «индекса продуктивности»       |
| is_archived   | BooleanField (default False)          | мягкое удаление, чтобы не ломать историю |
| created_at    | DateTimeField                         |                                       |

- **Дефолтные категории** засеиваются миграцией (data migration) или копируются
  пользователю при регистрации (signal `post_save` на User).
- Кастомные категории — CRUD пользователем.

### TimeEntry (свободные интервалы)
| поле          | тип                          | описание                          |
|---------------|------------------------------|-----------------------------------|
| id            | PK                           |                                   |
| user          | FK(User)                     |                                   |
| date          | DateField                    | день записи                       |
| start_time    | TimeField                    | начало интервала (10:15)         |
| end_time      | TimeField                    | конец интервала (11:40)          |
| category      | FK(Category), nullable       | что делал                         |
| note          | CharField, blank             | свободный комментарий            |
| created_at    | DateTimeField                |                                   |
| updated_at    | DateTimeField                |                                   |

**Валидация:** `end_time > start_time`; предупреждение/запрет пересечения
интервалов в рамках одного дня (настраиваемо). Длительность считается на лету.

## 3. Структура страниц (роуты)

1. **`/login`, `/register`** — аутентификация (JWT).
2. **`/` (День / Сегодня)** — главный экран ввода. Mobile-first.
   - Выбор даты (по умолчанию сегодня), стрелки ←/→ по дням.
   - **Список интервалов** (по умолчанию ~10 пустых строк): слева поля времени
     `start–end`, справа выбор категории + поле заметки.
   - **Авто-подсказка времени:** start новой строки = end предыдущей.
   - Добавление новой пустой строки кнопкой «+».
   - Автосохранение (debounce) или явная кнопка «Сохранить».
   - **Мини-визуал прямо тут:** горизонтальная «лента дня» 00:00–24:00, раскрашенная
     по категориям + donut распределения за день.
3. **`/stats` (Статистика)** — неделя / месяц / произвольный период.
   - Переключатель периода (неделя / месяц / кастом).
   - Графики (см. раздел 4).
   - KPI-карточки.
4. **`/categories`** — управление категориями (CRUD кастомных, выбор цвета/иконки/типа,
   архивирование).

Навигация — нижний таб-бар на мобилке (День / Статистика / Категории / Профиль).

## 4. Графики и визуализация

### Страница «День»
- **Лента дня (horizontal stacked bar 00:00–24:00)** — наглядно, что и когда.
- **Donut по категориям** — распределение времени за день.

### Страница «Статистика»
- **Stacked bar по дням** — столбец = день, сегменты = категории.
- **Линейный график трендов** — динамика выбранных категорий по дням.
- **Календарь-heatmap** (в стиле GitHub) — цвет = время на категорию/тип. Для привычек.
- **Топ категорий** — рейтинг с часами и % за период.
- **KPI-карточки:**
  - всего заполнено часов,
  - продуктивное / нейтральное / «пожиратели» (по `kind`),
  - средн. часов в день,
  - **Индекс продуктивности** = productive-время / всё заполненное время (%).

## 5. Анализ дня (ключевая фича — продумано)

- У каждой категории есть **тип `kind`**: `productive` / `neutral` / `waste`.
- На основе типов считается **индекс продуктивности дня** и его тренд по неделям.
- Фильтры в статистике по категории и по типу.
- Сравнение «план vs факт» можно добавить позже (цели по категориям на день/неделю).

## 6. API (REST, JWT)

```
POST   /api/auth/register/         регистрация
POST   /api/auth/login/            получить access+refresh
POST   /api/auth/refresh/          обновить access

GET    /api/categories/            список (дефолтные + свои, без архивных)
POST   /api/categories/            создать кастомную
PATCH  /api/categories/{id}/       изменить
DELETE /api/categories/{id}/       архивировать (мягко)

GET    /api/entries/?date=YYYY-MM-DD          записи за день
POST   /api/entries/                          создать
PATCH  /api/entries/{id}/                      изменить
DELETE /api/entries/{id}/                       удалить
POST   /api/entries/bulk/                       массовое сохранение строк дня

GET    /api/stats/?from=&to=&group=day|category|kind   агрегаты для графиков
```

- Все `entries`/`categories` фильтруются по `request.user` (нельзя видеть чужое).
- Агрегация статистики — на стороне Django (ORM `annotate`/`aggregate`), фронт
  только рисует.

## 8. Доступность (a11y)
- Семантические теги, корректные `<label>` для всех полей ввода.
- Таблица дня — навигация с клавиатуры (Tab/Enter переход между строками).
- ARIA-атрибуты для интерактивных элементов и графиков (текстовые альтернативы).
- Контраст по WCAG AA; не полагаться только на цвет категорий (иконки/подписи).
- `prefers-reduced-motion` для анимаций.
- Проверка `eslint-plugin-jsx-a11y` в CI.

## 9. Этапы реализации (milestones)

1. **M0 — Каркас.** Репозиторий, docker-compose (postgres), Django-проект, Vite-проект,
   линтеры, pre-commit, базовый CORS, «hello world» фронт↔бэк.
2. **M1 — Аутентификация.** Регистрация/логин, JWT, защищённые роуты, сид дефолтных категорий.
3. **M2 — Категории.** Модель + CRUD API + страница управления.
4. **M3 — День (ядро).** TimeEntry API + bulk, страница ввода (10 строк, авто-время,
   автосохранение), лента дня + donut.
5. **M4 — Статистика.** Агрегаты на бэке + страница с графиками и KPI + индекс продуктивности.
6. **M5 — Полировка.** A11y-аудит, мобильная адаптивность, пустые состояния, тесты, README.
